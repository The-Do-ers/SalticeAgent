1. Executive Summary & Mission

[Core Engine: multi_agent_cli / engine.py]

Saltice is a high-performance, autonomous pair programming agent engineered to bridge the gap between human intent and production software. Built on the SalticeAntigravityEngine, it provides resilient dual-mode response parsing (native JSON tool calling with automatic Markdown recovery), progressive skill discovery, multi-turn token pruning, and subagent delegation.

Unlike fragile wrapper agents that stall in infinite syntax error loops or blow out 64k token windows on verbose file writes, Saltice embeds Microsoft Loop & Context Engineering, Headroom Content-Centric Representation (CCR), and Chrome DevTools MCP directly into its core decision cycle.

🧠 Andrej Karpathy's 4 Golden Principles

  • Think Before Coding: Explicitly surface assumptions, constraints, and tradeoffs before writing code. Clarify ambiguity.
  • Simplicity First: Minimum code that solves the problem. No speculative configurability or single-use abstractions.
  • Surgical Changes: Touch only what you must. Use replace_file_content rather than rewriting entire files. Zero orphan files.
  • Goal-Driven Execution: Loop through automated build checks and tests until verified complete.

🛡️ Strict Safety Guardrails

  • Zero White-Screen Policy: No stub comments (/* TODO */). Every component is 100% complete and functionally closed.
  • Dev Server Lockout: Hard pre-tool hook blocks blocking servers (npx vite, npm run dev) from freezing the agent loop.
  • Living Documentation Triple-Pack: Requires implementation_plan.md, walkthrough.md, and README.md.
  • Rate Limiting & Exponential Jitter: Automatic retry on API 429/503 limits with sliding-window RPM/TPM tracking.

3. Token Optimization & Loop Engineering

[Microsoft Lesson 12 + Cobus Greyling + Headroom CCR]

📉 89.7% Context Scrubbing

Multi-turn conversations retain recent turn memory verbatim, while prior turns have multi-thousand character disk write outputs converted into lightweight receipts: [Content written to disk: App.tsx (4.2kb), syntax verified]. Context size dropped from 6,476 chars to 668 chars in tests.

⚡ Loop Stall Circuit Breaker

Tracks normalized observation signatures. If an identical error is encountered 2 turns consecutively, injects a reflection warning. At turn 3 or 4 of repeated failure, halts execution and outputs a root-cause diagnosis, preventing token burn.

📦 Headroom CCR & Distillation

Tool outputs exceeding 3,000 chars are saved to .saltice/tool_logs/. The agent receives a 1,200-char distillation (head + tail + fatal error lines) with a retrieval receipt. SmartCrusher structurally compresses JSON by >95%.

5. Asynchronous Subagent Swarm (10 Personas)

[subagents.py • Parallel Thread Execution]

🤖 10 ECC Specialized Roles

  • planner: Decomposes complex goals into granular, testable steps.
  • architect: System design, high cohesion, low coupling boundaries.
  • tdd-guide: Defines tests first (unit/integration) with strict coverage.
  • code-reviewer: Audits logic, edge cases, readability, performance.
  • security-reviewer: OWASP Top 10, secret leak, input sanitization auditor.
  • build-error-resolver: Quickly fixes compilation, type, and lint failures.
  • doc-updater: Synchronizes implementation plans, walkthroughs, READMEs.
  • academic-researcher: Literature synthesis, citation verification.
  • karpathy-auditor: Enforces simplicity, kills speculative complexity.
  • browser-agent: Headless Chrome DevTools DOM, console, and a11y testing.

⚡ Non-Blocking Swarm Workflow

Subagents run in daemonized background threads, allowing the primary agent or user to continue planning without freezing the shell:

# Main agent spawns worker:
task_id = spawn_subagent(
    role="browser-agent",
    prompt="Inspect http://localhost:3000 for console errors"
)

# Non-blocking poll or wait:
status = check_subagent_status(task_id)
result = wait_for_subagent(task_id, timeout_sec=60)
