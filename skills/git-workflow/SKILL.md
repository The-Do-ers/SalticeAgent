# Git Workflow & Version Control Skill

## When to Use
Use when creating commits, inspecting git diffs, branching, staging changes, or resolving conflicts.

## Guidelines
1. Always run 'git status' and 'git diff' before staging to verify only intended files are modified.
2. Use Conventional Commits format:
   - feat: new feature
   - fix: bug fix
   - refactor: code restructuring without changing behavior
   - test: adding or updating tests
   - docs: documentation updates
3. Never force push or discard changes without user confirmation.
4. Keep commit messages concise, descriptive, and imperative (e.g., 'feat: add rate limit shield to providers').
